# Noma v0.1 audit (2026-10-04)

Read against the source on `main` at d841e7b, before the v0.1 changes. The
baseline was 522/522 tests passing and a clean typecheck. Older audits
(`product-audit.md`) describe a much earlier app and are mostly out of date.

## Working today (verified in code, and in earlier sessions on the dev laptop)

- **Foreground-app detection** (Windows: koffi + PowerShell watcher) and
  per-app 4-slot profiles. VS Code, Chrome and Spotify ship with starter
  profiles; any other app can get one (Profiles, or Home's "Create profile").
- **Real execution** of shortcuts, macros, the safe `closeWindow` (WM_CLOSE),
  system commands, app focus and named-button clicks (UI Automation), with a
  one-at-a-time lock, a blocked-combo list and "Stopped at step N of M" errors.
- **Glide recognizer** (`main/holo/trackpadGesture.ts`): pure, tested,
  thresholds tuned on one real touch check (ASUS Precision Touchpad, G14).
  Raw HID through one shared WM_INPUT hook; pointer put back after a swipe.
- **Flow capture → detection → suggestion**: modifier-only capture policy,
  hard "makes sense" rules (`workflowSense.ts`), learned quality filter,
  fingerprint dedupe, bottom-centre Noma Notice toast. Suggestions never
  run anything; accepting asks the user to pick a slot.
- **Persistence**: SQLite for profiles, controls, macros, suggestions,
  onboarding, settings. Single-instance lock. Tray with Open / Quit.

## Critical bugs and blockers

1. **Demo Mode can wipe a tester's real data.** `resetDemoData()` deletes
   *every* workflow event and suggestion, and Demo and Developer are in every
   user's sidebar. Demo events are also written as ordinary events, so the
   Bookmark → Close tab suggestion looks exactly like something Noma learned.
2. **Glide only works through the renderer and two hidden switches.** The
   on/off state lived in `localStorage`, the auto-start also required
   Settings > Input Source = Glide, and the swipe → press step ran in the
   renderer (`holoStore.pressSlot`). Turning Glide on from its page without
   changing Input Source made it stop when you left the page.
3. **Glide runs actions behind Noma's own window.** While Noma is in front,
   the "current app" is the last real app behind it, so trying a swipe on the
   Glide page could press Chrome's *Close window* in the background.
4. **You approve a workflow without seeing what will run.** The macro built on
   accept can add steps the card never shows (an Enter after a trailing
   paste, focus steps, delays), and the card doesn't say which steps can't
   be replayed.
5. **No way to remove or pause a learned workflow**, other than resetting the
   control it sits on. **No way to stop** a multi-step replay once started.
6. **Shutdown leaves the Glide service running** until process exit
   (`window-all-closed` stops capture but not the trackpad service).

## UX problems

- Onboarding (6 screens) still says "Your keyboard adapts to you", has a
  use-case survey nothing reads, a hardware screen about a virtual keyboard,
  and an animated fake demo. Glide is never mentioned, and nothing gets the
  user to a working action.
- Glide zones show the current app's controls but can't be edited there, and
  slots are called "Control 1-4" everywhere else, so "which swipe does this
  workflow live on" is never answered.
- 15 sidebar items. Controls, Profiles and Glide overlap; "Noma Device" needs
  a separate simulator app; Demo/Developer are engineering tools.
- Unknown apps have no controls, so a swipe does nothing, with no in-app hint
  beyond the Glide page's last-outcome line.
- No way for a beta tester to report a problem.
- Successful Glide presses in another app give no feedback inside Noma.

## Tests

Good coverage of detection, sense rules, quality model, execution safety,
repositories and the gesture detector (synthetic frames). Missing: recorded
touch traces as regression fixtures, Glide slot/zone mapping and the
"Noma in front" rule, workflow removal/disable, cancellation, demo isolation,
onboarding v0.1, startup/shutdown of the Glide service.

## Implementation order

1. Demo isolation + hide engineering tools (data-loss risk first).
2. Glide owned by main: one persisted on/off switch, presses from main,
   practice mode while Noma is in front, stop on quit.
3. Flow: step preview before approval, remove/disable, cancel a run,
   demo badge.
4. Connect them: Glide page as the action map (pick app, see and change each
   zone), slot labels named after Glide zones.
5. Onboarding: four short screens ending in a first real action.
6. Navigation, bug report, beta guide, docs, tests.
